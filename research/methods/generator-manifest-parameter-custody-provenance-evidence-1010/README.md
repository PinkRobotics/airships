# Manifest header namespaces versus actual input custody

This paper traces selected input-container identities in [tools/gen_nodes.py](../../../tools/gen_nodes.py). [CROSSWALK.json](CROSSWALK.json) records exact nonnumeric fragments, hashed lexical context and prospective missing records. [PROVENANCE.json](PROVENANCE.json) pins complete sources and revision. It supplies no acquired generated manifest, verified input configuration or physical verification.

Inside `main`, the selected `manifest` declaration has a `paramsMm` namespace containing a `prm[k]` source reference. The selected `graph`, `jointCheck` and `res` fields reference `tally`, `joint` and `args.res` respectively. These are selected source input-container/argument identities, not an exhaustive generator/output-schema map. No parameter comprehension, field list, rounding rule, formula, numerical values or algorithm is reconstructed or evaluated. Identical spelling elsewhere does not establish the same lexical binding.

A namespace suffix is not measured dimensions, validated fixture inputs or an as-built register. `graph` is not a newly verified physical inventory and `jointCheck` is not an acquired physical check or certified connection. `res` names a source argument, not a chosen resolution or qualified source-to-article applicability.

The selected final source writer uses the manifest.json path with `write_text` and `json.dumps(manifest,...)`. This locates serialization call identity only, without copying its numeric argument or reconstructing/executing serialization. No generator manifest is serialized, regenerated, looked up, freshly matched or acquired for this paper; source hashes do not supply actual output digest/custody.
