# Same-lake interface evidence custody

The [verification plan's external operations question](../../../docs/VERIFICATION-PLAN.md#what-we-would-ask-external-evaluators) asks whether the conceptual vehicle would compete with skimmers for the same lakes. Its [missing-evidence list](../../../docs/VERIFICATION-PLAN.md#what-is-still-missing-entirely) separately describes competition with the existing fleet. These are published questions and scope statements, not observations of a demonstrated shared-use interface.

Geographic water measures, conditional aircraft throughput and actual shared use need separate evidence. [The existing availability question](../../../docs/OPEN-QUESTIONS.md#13-water-geometry-is-measured-operational-availability-remains-open) already leaves operational availability open. This paper neither repeats its availability rows nor supplies a water-source, draw, capacity or throughput result. It selects and names no site or lake.

[EVIDENCE-MAP.json](EVIDENCE-MAP.json) retains the exact competition wording, evaluator question, existing availability scope limit and public publication-custody labels. The prospective rows concern matched identity, interval, occupation/access, concurrent demand/activity, timing/state association, calibration/uncertainty and custody of an actual interface record. They provide no operational route, schedule, traffic separation, procedure or tactic. [PROVENANCE.json](PROVENANCE.json) pins the unchanged assigned sources.

The operations-chief role is requested by the source; no person, operator, custodian or acceptance owner is assigned here. The [README's Builder, checker/verdict and audit labels](../../../README.md) describe publication provenance rather than physical interface evidence. The same README states no aircraft has been built or flown and separates repository checks from aircraft feasibility. Actual record custody and adopted interface criteria remain unknown.
