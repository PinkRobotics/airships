# Named source basis selector and actual adoption provenance

The [model source](../../../ship/model.js) defines `shipBasis(basis, knockdown)`. Its `record` string denotes a computational selector, not an acquired validation record or accepted scientific basis. `favourable` is a source name, not qualified physical permission. The source interface comment preserves legacy named calls; this paper records lexical parameter/string/caller identities without selecting a world, factor, mode or credit.

Under null `basis`, source null or named `SHIP0.giKnockdown` maps to `record`, and named `SHIP0.giKnockdownFrame` maps to `favourable`. Other null-basis combinations carry the custom-knockdown explicit-basis error. Explicit `basis` is checked against the allowed `record` and `favourable` strings with a separate error identity, and `shipBasis` returns the source selector. These legacy aliases, explicit selector and rejected custom combinations are source-interface context only; no branch was executed and no new regression or correctness proof is supplied.

`shipSkeleton` and `ship0` each have a null-default `basis` parameter and normalize their local selector through `shipBasis`. `ship0` uses that local selector in named-default input context and forwards it to `shipSkeleton`. These are parameter/local/caller identities, not an invented returned basis field, actual input custody, approved property/load domain or adoption decision.

[EVIDENCE-MAP.json](EVIDENCE-MAP.json) pins exact nonnumeric fragments and source-context span hashes. [PROVENANCE.json](PROVENANCE.json) pins unchanged sources.
