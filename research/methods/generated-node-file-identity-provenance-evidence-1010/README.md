# Node output labels versus manufactured part registry custody

This paper traces selected source identities in [tools/gen_nodes.py](../../../tools/gen_nodes.py). [CROSSWALK.json](CROSSWALK.json) records exact nonnumeric fragments, hashed lexical context and prospective missing records. [PROVENANCE.json](PROVENANCE.json) pins complete sources and revision. It acquires no generated file, original manifest or manufactured part registry.

The `write_stl` signature names `path`, `verts` and `tris`. Within `main`, the selected `out` namespace, `args.only` context and `i, u, role` loop locate the output/iteration source scope. A bare `name =` fragment locates the selected name assignment without defining or reconstructing its filename-generation expression. The selected per-node writer consumes `out / name`, `v` and `t`. These are selected source identities, not a comprehensive use inventory, evaluated index/location/count or verified generated-output correspondence.

The source manifest has a `nodes` namespace. The selected appended row exposes `file` from `name`, `u` from its selected source variable and `role` from `role`. A separate selected writer uses the source manifest.json path. A source file label and row role/location are not an issued physical serial, actually printed inventory, installed registry entry or inspected part. Same spelling in another scope does not establish the same lexical binding.
