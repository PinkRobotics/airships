# Stability-reserve comparison-basis provenance

[Reserve omitted on the favourable basis](../../../docs/OPEN-QUESTIONS.md#reserve-omitted-on-the-favourable-basis) asks whether the favourable figure should include its omitted stability reserve and which imperfection allowance should govern that comparison. This paper keeps the record/favourable source comparison and unresolved question. It adopts no allowance or criterion, answers no design question and supplies no corrected model or physical feasibility claim. Historical source counts, masses, knockdowns, reserve and safety-factor values stay only in the unchanged sources.

The current [model](../../../ship/model.js) validates explicit named basis labels through shipBasis. Legacy null-basis calls infer record/favourable from named knockdown identities; other custom knockdowns require explicit basis. ship0 chooses a named default knockdown when no override is supplied and forwards the declared basis and source material/safety inputs to shipSkeleton. These are code contracts, not physical adoption or measured material provenance.

The reserve branch is conditional. After the initial source sizing, the skeleton compares imperfection worlds. An insufficient shell-world diagnostic and record basis permit the additional sizing branch, and only a successful follow-up source margin charges additional increments. Favourable basis skips that branch; record basis alone does not guarantee charged reserve. The uncharged code state is not measured absence, a negligible requirement or proof of adequacy. No numerical margin threshold or source coefficient is copied or adopted here.

The [member census](../../../docs/MEMBER-CENSUS.md#recorded-disagreements) names stabilityReserve as additional solved areas with no separate drawing, and records no complete drawn allocation. Unknown mass is never zero. A bill line or smeared source check cannot supply complete station/member/connection identities, observed material/configuration, calibration or an adopted allowance. The code's uncharged branch and the census's unknown counterpart are distinct kinds of absence and must remain separate. Reserve uses local second-minus-first area differences within the conditional expression; those increments are not separately returned. The baseline inner-ring, theta-web, flange and spoke keys identify ordinary members, and the baseline theta area also changes in the later cap loop. They must not be used as reserve-increment locators.

Prospective evidence requires the original source domain/revision, material and configuration identities, imperfection/basis provenance and comparison inclusion/exclusion, applicable matched evidence, raw source custody, calibration, uncertainty and responsible adoption source/version/applicability. All actual material/configuration/basis/inclusion/matched/raw/calibration/uncertainty/applicability/custody records, assigned owners, adopted allowance and adopted criterion remain NULL/UNKNOWN. Roles are prospective custodians only, UNASSIGNED. [PROVENANCE.json](PROVENANCE.json) pins the authoritative inputs and baseline revision.

P16 physical collapse/eigenvalue work, Q0/Q11 mass/size, Q20 normalization, Q15 operational failure strategies, acceptance-role index and membrane shape/volume remain separate. This paper concerns only unresolved comparison-basis reserve inclusion and adoption-source custody. It changes no source/model/test/schema/catalogue/data and runs no model, generation, fixture or solver. No reserve/strength/lift/volume/mass calculation, selected material/geometry/design/procedure, physical action, external lookup, new measurement or scientific outcome is supplied. The root README says no aircraft has been built or flown; source accounting and repository checks cannot establish feasibility, qualification, benefit or safety.
