# Comparable-report source namespaces versus comparison custody

This paper traces selected source identities in [tools/check_assembly.py](../../../tools/check_assembly.py). [CROSSWALK.json](CROSSWALK.json) records exact nonnumeric fragments, hashed lexical context and prospective missing records. [PROVENANCE.json](PROVENANCE.json) pins complete sources and revision, including separately retained generator input context. No produced reports, comparison result or physical measurement is acquired.

`comparable_report` owns a `report` parameter and a local `clean` binding that is returned. A bare `clean =` locator deliberately stops before the expression and does not define an algorithm. Selected source text names `runtimeS`, `fieldS` and `verdict`. These are namespace/key identities, not a complete report-key inventory, float-tolerance discussion, numerical values or physical timebase. Same spelling in another scope is not assumed to be the same lexical binding. No comparison/deletion/serialization/branch/dictionary algorithm or formula is reconstructed or evaluated.

The docstring describes comparing physical results while omitting host-duration measurements. That wording remains attributed computational intent. It does not independently supply actual physical measurements, exhaustive validated comparison, current correctness, identity of produced reports or scientific/physical acceptance. Source names, hashes and software gates cannot establish report-pair or comparison-result custody.
