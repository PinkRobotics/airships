# Question 9: real day/night recovery evidence requirements

Date: 2026-10-10. Status: prospective method, OPEN. [Question 9](../../../docs/OPEN-QUESTIONS.md#9-how-long-can-recovery-take-through-a-real-day-and-night) asks how storage and charging losses alter recovery when instantaneous sunlight is zero. The existing [issue 8](https://github.com/PinkRobotics/airships/issues/8) is retained; no remote action occurs here.

The published day-average and lossless energy quotients remain historical model results. The existing ground-tank sensitivity is a constant-average analytic balance with two different loss denominators, bounded by installed capacity. It provides no cold-state or power-buffering schedule and establishes neither recovery impossibility nor achievable recovery. This paper does not calculate energy, simulate charging or predict duration.

The [evidence contract](EVIDENCE.json) maps the missing synchronized solar, charging, production, loss and boundary records to public source fields. Every observation, evidence-record reference, measured uncertainty and physical criterion is null. Q9 identifiers reserve future records, not acquired evidence.

Each future record must retain timestamps and time-zone/calendar basis, article/component identity, calibration, sampling interval, synchronization error, uncertainty and missing-data flags. Power, flow and inventory histories must use the same phase and system boundary; daily averages cannot fill missing night observations. Preserve cloudy periods, outages and failed starts alongside favourable observations. Criteria for acceptable uncertainty, duration, losses and recovery remain UNKNOWN pending a separately recorded decision.

The existing code distinguishes loss proportional to installed capacity from loss proportional to current inventory. Its local ground-comparator record carries published source locators, but no comparison to an airborne tank is made here. This thread reads and pins the existing local record; it does not independently validate external literature, select storage hardware or transfer its loss rates. The original tables, equations and conclusions are unchanged.
