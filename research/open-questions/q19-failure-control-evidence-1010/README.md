The dated open question reports a rotor allocator path and six non-rotor drawing-only failure controls. That historical record remains verbatim. This paper traces the present source consumers without pressing a button or executing the model. It does not newly measure identical allocations or mark the omission fixed.

The lab merges manual and clip failures into failedComponents. The readout and viewer allocation paths disable matching actuator IDs before calling allocate, whose live set excludes disabled entries. Primary rotor station IDs match that bank. The bank also contains medium thrusters and trim fans; the six reported bus, generator, pump, cell, sensor and tail IDs do not name those actuator types. The allocator's own source says it is a visualization and systems-explanation model, with no demonstrated stabilization.

The six controls have readers beyond a colour change: flags are forwarded through visual state, render styling and state descriptions. A failed pump triggers animation-local hose/pod release; a failed tail changes the drawn hinge deflection. Those effects must not be described as absent, nor relabelled hydraulic failure, aircraft load transfer or an aerodynamic tail-failure model. The current electrical picture reads supplied telemetry and retains unavailable mission energy as unknown. It does not derive bus or generator failure from the component flag. The mass display likewise does not turn a failed cell ID into a leak/pressure/displacement history.

Prospective causal evidence would need the exact source/configuration, declared inputs and failure event, matched before/after model state and output records, and the consumer responsible for each change. Visual changes, allocator outputs and equipment/aircraft outcomes belong to different domains. The source scope must be declared before any claim of failure simulation. Actual records and physical criteria remain unknown. This paper neither implements missing wiring nor selects a physics module, runs a campaign or makes a safety assertion; it does not duplicate Q14 dynamics.
