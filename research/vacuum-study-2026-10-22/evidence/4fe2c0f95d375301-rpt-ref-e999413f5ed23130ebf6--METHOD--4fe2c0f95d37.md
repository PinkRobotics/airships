# MAINLINE-030d — preservation and synthesis method

QUESTIONABLE / PROJECTION. This register extends 030c's source identity, snapshot, topic routing and ledger workflow. The full 030c manifest, including its build code and nested 030b history, is retained under `baseline030c`. No numerical source model is imported, copied into a solver, or executed by this register.

1. intake.py verifies the canonical 030c report and every manifest entry, preserves bytes, and snapshots new canonical reports after 04:03:32 PDT excluding every report already indexed by 030c. All direct artifact pins are verified. New numerical results come only from filed reports. An operational exception can be included without treating its numerical card as complete.
2. normalize.py preserves complete NFI records, including nested inherited documents. Identity is report, original file and JSON pointer. Every complete finding keeps its fields; auxiliary metadata and document-level qualifications remain inNEW-NFI-SOURCES.json. Attributed duplicates are not counted as independent physical gaps.
3. build_register.py preserves all 98old rows and 961 findings, both ledgers and all grounding routes. New findings receive one primary topic through recorded rules and source-specific defaults. Current 030d annotations coexist with the immutable history. Every newly ingested report must have an explicit semantic change disposition or the build stops.
4. Selected 048 and all 45 052 scenario points and bills are copied from filed data. Summation, mode minima, gamma/Q/film ratios, the same-allocation extra 50 kg service debit, historical 433 t/430 t supply shares and conditional Weibull hazard inversion are the only new arithmetic. The 052 source comparison used original 048; its cure-included comparison is separate fixed-point arithmetic. No geometry optimization, finite-element solve, new source research, life qualification or damage-model rerun is claimed.
5. write_docs.py renders the morning summary, one line per change, full bill, damage/life matrix, corrected proof and manufacturing statements, complete attributed registers and ledgers. Historical false labels remain only as attributed source history; current annotations give corrected values.
6. validate_packet.py checks byte/field preservation, every source pointer and routing identity, ledger/grounding preservation, required corrections, selected arithmetic, source coverage, pending dispositions and rendered file links. These are register-integrity checks, not independent certifications of source models.

Reproduce: run normalize.py, build_register.py, write_docs.py, validate_packet.py in this directory with Python 3. Refresh intake.py only while deliberately incorporating additional filings; each new report requires explicit disposition. Final filing records one frozen source boundary. A final canonical scan checks for any unincorporated report immediately before submission.
