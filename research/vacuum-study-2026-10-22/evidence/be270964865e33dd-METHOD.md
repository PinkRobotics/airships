## Future deltas

Use an explicit JSON delta with these fields:

```json
{
  "id": "DELTA-PIECE-B-EXAMPLE",
  "expected_version": 3,
  "at": "an actual measured timestamp",
  "meaning": "Describe the newly filed evidence",
  "append_findings": [],
  "amend_findings": [],
  "append_register_rows": [],
  "append_source_catalog": [],
  "append_administration": [],
  "set_sections": {}
}
```

Use the current record's actual version, not the example value. Each appended finding needs a unique stable `id`, `kind`, `claim`, numerical status, physical qualification, and `sources` containing the exact report, original artifact path, local snapshot, SHA-256, size and selector. Amend an existing ID using `changes`, `reason` and `sources`; do not replace its immutable `id`, `kind` or `original` fields. The prior values remain in the amendment history.

`append_changes` adds the registered finding's short morning-card line. `append_nfi_rows`, `append_ledger_rows` (keys `corrections` and `optimism`) and `append_grounding_routes` preserve their existing prefixes. To update the current narrative or replace a selected scenario, set `card_template` through `set_sections` in the same evidence-bearing delta; retain `{{record_header}}`, `{{coverage_summary}}` and `{{change_lines}}`. The immutable delta preserves the previous version's provenance. Do not silently promote an unreviewed fix or close a physical question while changing presentation.

`apply_delta.py` rejects stale versions, repeated delta IDs, duplicate finding/row IDs and unsupported metadata changes. It verifies amendment/appended-finding evidence hashes, stores the immutable delta in `deltas/`, and atomically replaces the canonical JSON. It does not send messages, file reports, dispatch work or run a scientific model.

```text
python3 apply_delta.py /absolute/path/to/new-delta.json
python3 render030e.py
python3 validate030e.py
```

Run these from this output directory with the authorized resource wrapper when required. The wrapper supplied here expects the repository root as its working directory; use it as the recorded receipts do. `bootstrap030e.py` refuses to run if a canonical record exists. Never delete that guard's input to rebuild later pieces.

## Validation

`VALIDATION.json` checks complete baseline preservation, unique IDs, direct source pins, numerical/physical status separation, exact correction values and labels, record-to-view consistency, review inventory, all ten wording repairs, 22 token repairs, and stale/duplicate-delta rejection. It does not review the proposed fixes a second time or qualify any physical claim.

All requested card/check/review releases are folded. The handoff is this versioned record, source snapshots, immutable deltas and deterministic views. No follow-on job is assigned by this register.
